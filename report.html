1. Тема та мета роботи

Тема: Основи HTML5. Семантична верстка багатосторінкового вебсайту.

Мета: навчитись створювати семантично коректну структуру багатосторінкового вебсайту з використанням HTML5; опанувати принципи логічної організації контенту; забезпечити коректну навігацію між сторінками та підготувати основу для подальшої стилізації й адаптивної верстки.

2. Теоретичні відомості

2.1 Семантичні теги HTML5

Семантична верстка — підхід, за якого кожен HTML-елемент несе смислове навантаження, що дозволяє браузерам, пошуковим системам та допоміжним технологіям (скрін-рідери) правильно інтерпретувати структуру сторінки. HTML5 запровадив низку семантичних тегів:

  • <header> — шапка сторінки або секції; містить логотип та навігацію
  • <nav> — блок навігаційних посилань
  • <main> — основний унікальний контент сторінки (лише один на сторінці)
  • <section> — тематична секція з власним заголовком
  • <article> — самодостатній незалежний блок контенту (новина, страва, картка)
  • <aside> — бічний контент, пов'язаний із основним, але другорядний
  • <footer> — підвал сторінки або секції
  • <address> — контактна інформація автора або закладу
  • <time> — дата або час у машинозчитуваному форматі
  • <figure> / <figcaption> — ілюстративний матеріал із підписом

2.2 Доступність (Accessibility) та ARIA

ARIA (Accessible Rich Internet Applications) — набір атрибутів, що розширюють семантику HTML для допоміжних технологій. Ключові атрибути:

  • aria-label — текстове позначення елемента для скрін-рідера
  • aria-labelledby — посилання на видимий елемент, що слугує міткою
  • aria-describedby — посилання на елемент із додатковим описом
  • aria-required="true" — позначає обов'язкові поля форми
  • aria-current="page" — позначає поточну сторінку у навігації
  • role — явно задає роль елемента (наприклад, role="img", role="group")

2.3 Структура форми

Доступна форма HTML5 будується на таких принципах: <fieldset> групує пов'язані поля, <legend> описує групу, кожне поле <input>, <select>, <textarea> пов'язане з <label> через атрибут for/id. Атрибути required, type, min, max, pattern забезпечують нативну валідацію браузера.

3. Хід роботи

3.1 Структура проєкту

Для виконання роботи було створено веб-сайт ресторану «Old Street» (м. Кам'янець-Подільський). Сайт складається з трьох HTML-сторінок та одного файлу стилів: 

Old_Street/
├── index.html       ← Головна сторінка
├── menu.html        ← Сторінка «Меню»
├── booking.html     ← Сторінка «Бронювання»
├── css/
│   └── style.css    ← Базова стилізація
└── report.html      ← Цей звіт

3.2 Головна сторінка (index.html)

Мета сторінки

Головна сторінка презентує концепцію ресторану, ключові переваги, графік роботи та містить навігацію до інших розділів.

Семантична структура

Сторінка побудована за такою ієрархією семантичних тегів: 

<header>  — логотип + <nav> з навігаційними посиланнями
<main>
  <section aria-labelledby="hero-heading">     — секція-привітання
  <section aria-labelledby="about-heading">    — концепція ресторану
    <section aria-labelledby="features-heading"> — вкладена підсекція «Переваги»
      <ul> → <li> → <article>                   — картки переваг
  <section aria-labelledby="hours-heading">    — графік роботи
    <table>                                       — таблиця годин
  <section aria-labelledby="location-heading"> — розташування
<footer>
  <address>  — контактна інформація ресторану

Використання тегу <address>

Згідно зі специфікацією HTML5, тег <address> у <footer> позначає контактну інформацію закладу: фізичну адресу, телефон, e-mail та посилання на онлайн-меню. Застосований атрибут aria-label для опису скрін-рідером: 

<address class="footer-contacts"
         aria-label="Контактна інформація ресторану">
  <p><a href="https://maps.app.goo.gl/...">
    Старе місто, Кам'янець-Подільський, 32300
  </a></p>
  <p><a href="tel:+380674001234">+38 (067) 400-12-34</a></p>
  <p><a href="mailto:info@old-street.com.ua">...</a></p>
</address>

3.3 Сторінка «Меню» (menu.html)

Структура категорій

Меню розбите на 6 категорій-секцій. Кожна категорія — окремий <section> з унікальним id для якірної навігації. Кожна страва — <article>, що є самодостатнім блоком контенту.

ARIA-мітки для алергенів

Відповідно до вимог варіанту, кожна страва, що містить алергени, позначена значками з атрибутами role="img" та aria-label із детальним описом алергену: 

<div class="dish-tags" role="group"
     aria-label="Алергени страви «Борщ Старомістський»">
  <span class="allergen-badge badge-g"
        role="img"
        aria-label="Алерген: глютен — пампушки з пшеничного борошна">Г</span>
  <span class="allergen-badge badge-l"
        role="img"
        aria-label="Алерген: лактоза — подається зі сметаною">Л</span>
</div>

ARIA-мітки для гостроти

Рівень гостроти позначається елементом <meter> — стандартним HTML5-елементом для відображення числового значення у межах діапазону. Атрибут aria-label забезпечує доступне текстове пояснення: 

<meter class="spicy-meter"
       min="0" max="3" value="2"
       aria-label="Гострота: 2 з 3 — помірна гострота"
       aria-describedby="spicy-label-o5">
  Помірна гострота (2 з 3)
</meter>

Легенда позначень

На початку сторінки розміщений блок <aside> із легендою, що пояснює значення кожної абревіатури алергену та шкали гостроти. Застосовано семантичний тег <dl> (список визначень):

3.4 Сторінка «Бронювання» (booking.html)

Структура форми

Форма бронювання організована в 7 тематичних групах <fieldset> з відповідними <legend>. Це забезпечує логічне групування полів та зрозуміле озвучування скрін-рідерами.

Структура форми бронювання
FieldsetЗмістКлючові елементи
1. Контактні дані Ім'я, телефон, e-mail type="text", type="tel", type="email"
2. Деталі резервації Дата, час, кількість гостей type="date", type="time", <select>
3. Тип події Привід зустрічі type="radio", role="radiogroup"
4. Розташування Зона у ресторані <select>
5. Харчові обмеження Дієтичні потреби type="checkbox", role="group"
6. Додаткові побажання Вільний коментар <textarea>
7. Підтвердження Згода з умовами type="checkbox", required

Елементи вибору дати та часу

Для вибору дати використовується <input type="date">, для вибору часу — <input type="time">. Атрибути min та max обмежують допустимий діапазон. Підказки прив'язані через aria-describedby: 

<input type="date" id="date" name="date"
       required aria-required="true"
       min="2025-01-01"
       aria-describedby="date-hint">
<p id="date-hint" class="form-hint">
  Ресторан відкритий щоденно з <time>11:00</time> до <time>23:00</time>
</p>

<input type="time" id="time" name="time"
       required aria-required="true"
       min="11:00" max="21:30" step="1800"
       aria-describedby="time-hint">

Доступність форми

Кожне поле пов'язане з міткою через for/id. Обов'язкові поля мають атрибути required та aria-required="true" і позначені символом <abbr title="обов'язкове поле">*</abbr>. Підказки (form-hint) прив'язані до полів через aria-describedby.

4. Організація навігації між сторінками

Кожна сторінка містить ідентичний блок <header> з елементом <nav aria-label="Основна навігація сайту">. Посилання реалізовані відносними шляхами (index.html, menu.html, booking.html). Поточна сторінка позначається атрибутом aria-current="page" — це стандартна ARIA-практика: 

<nav class="main-nav" aria-label="Основна навігація сайту">
  <ul>
    <li><a href="index.html">Головна</a></li>
    <li><a href="menu.html" aria-current="page">Меню</a></li>
    <li><a href="booking.html">Бронювання</a></li>
  </ul>
</nav>

Сторінка «Меню» також містить внутрішню якірну навігацію по категоріях: посилання виду <a href="#zakusky"> відповідають <section id="zakusky">.

6. Валідація HTML-коду

Валідація HTML-коду була виконана за допомогою онлайн-валідатора W3C Markup Validation Service (validator.w3.org). Перевірялися всі три сторінки: index.html, menu.html, booking.html.

За результатами валідації помилок не виявлено. Можливі попередження (warnings) стосуються порожніх атрибутів action="#" у формі та відсутніх зображень — вони є навмисними заглушками для подальшого розвитку проєкту.

7. Висновки

У ході виконання лабораторної роботи було розроблено тристорінковий вебсайт ресторану «Old Street» (м. Кам'янець-Подільський) з використанням стандарту HTML5.

Результати роботи:

  1. Створено семантично коректну структуру трьох сторінок із застосуванням тегів <header>, <nav>, <main>, <section>, <article>, <aside>, <footer>.
  2. На головній сторінці index.html реалізовано семантичний тег <address> у <footer> для контактної інформації ресторану.
  3. На сторінці menu.html здійснено структурування 6 категорій страв; кожна страва позначена ARIA-мітками алергенів (role="img", aria-label) та семантичним елементом <meter> для рівня гостроти.
  4. На сторінці booking.html реалізовано складну доступну форму бронювання столу з 7 групами <fieldset>, нативними елементами вибору дати (<input type="date">) та часу (<input type="time">), чекбоксами та радіо-кнопками.
  5. Усі сторінки пройшли валідацію W3C без критичних помилок.

Опановано принципи семантичної верстки HTML5, роботи з ARIA-атрибутами та побудови доступних форм. Отриманий результат є готовою основою для подальшої стилізації (CSS) та впровадження адаптивної верстки у наступних лабораторних роботах.
